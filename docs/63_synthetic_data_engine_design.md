> **TL;DR & takeaway**
> Design doc for adding a **SynthSeg/SynthMorph-style synthetic data engine** to this project.
> **None of this is implemented.** Core finding: the model is a *pure geometric transport
> operator* (point head emits Δ only; the splat moves input intensities verbatim), so the
> synthesis-engine preconditions are satisfied — but the highest-value item is **not** contrast
> randomization. It is **sampled-motion supervision**: `batch["resp_disp_mm"]` already carries
> exact GT displacement every training step and is **thrown away** (`grep` finds it only in
> `tools/`). Plan is staged S0→S4, cheapest-and-most-falsifiable first. Predicted payoff is
> **calibration + OOD robustness, not in-distribution PSNR** — docs/19 puts the model 0.5 dB from
> an architectural warp ceiling that no supervision change can move.

# 1. Why this is even applicable

The synthesis-engine literature (SynthSeg, SynthMorph, SynthSR, SynthStrip, anatomix) shares one
recipe: sample a label map → render appearance from it (per-label GMM + bias field + gamma + blur
+ resolution degradation + noise) → train against a target defined by **geometry**, not intensity.
It transfers to a new problem only when two conditions hold:

- **(A) Local conditional independence.** `I(x) ⊥ everything else | L(x)` — intensity at a voxel is
  generated by that voxel's own label. Broken by ultrasound (path-dependent shadowing, coherent
  speckle) and X-ray (line integrals over the whole volume).
- **(B) Sufficiency.** The target is a function of geometry alone, `Y ⊥ I | L`. Broken by
  histology, infiltrating pathology, and quantitative-intensity tasks (HU / ADC / SUV).

Widening the appearance priors is an operation on appearance parameters, so it **cannot repair a
violation of A or B**.

**Both conditions hold here, and (B) holds by measurement rather than assumption:**

- The point head outputs a residual Δ; `world_points = scanner_coords + Δ`
  (`model.train_on_residual_dvf: true`, `training/config/default.yaml`). It emits **no intensity**.
- `splat_predictions` (`vggt/utils/splat.py`) takes intensity verbatim from `batch["images"]` and
  trilinearly scatters it, dividing by accumulated coverage. Nothing downstream generates values.
- docs/19: directly optimizing Δ — no network, target-aware, every parameterization from rigid to
  free-per-pixel — tops out at **~21 dB** vs the trained model's **20.6** and a perfect-placement
  oracle of **35.0**. The 14 dB gap is the *appearance wall*: a displacement field can relocate
  input pixels but cannot change their values.
- docs/20 closed the escape hatch: feature-splat + 3D decoder = **+0.03 dB**.

So this model is, and will remain, geometry-only. That is condition (B), established by
experiment.

## 1.1 The photometric loss is geometric in disguise

`loss.py:195`: `loss_volume = (V_canon - V_gt).abs().mean()` — full-volume L1, no anatomy mask
(the masked variant sits commented out at `:194`).

This looks like it should forbid contrast randomization. It does not, because **inputs and target
are two views of one intensity field**:

- `gt_target_volume = phases_aug[arange(B), t_target]` — `gpu_aug.py:335`
- input slices are re-extracted from **the same** `phases_aug` — `gpu_aug.py:392` (or `:378` on
  the respiratory path)

The L1 residual is therefore purely a *placement* residual. This is enforced in code and the repo
already paid for the lesson once, in miniature — `gpu_aug.py:324-328` clamps the shared source
before deriving both branches precisely because otherwise "*V_gt can exceed 1 while the splat's
clamped inputs cap V_canon at ~1, leaving an unlearnable L1 residual (the point head predicts
position, not intensity)*".

**Consequence for any synthesis design:** replacing intensities `I → f(I, labels)` changes both
sides of the L1 through the same `f`, so the optimum in Δ is unchanged; only the loss *scale*
moves. This holds for **any** `f`. The design that must be **refused** is real `V_gt` with
synthetic inputs — that injects a systematic intensity bias with no channel in the architecture to
absorb it (the head emits Δ + an unused confidence), so gradient descent answers it by distorting
geometry.

# 2. The finding that reorders the whole plan

`gpu_aug.py:373-386` already samples the respiratory deformation and writes it to the batch:

```python
disp, resp_r = sample_resp_disp(...)
batch["resp_disp_mm"]   # (B,S,3) mm, canonical (d_D, d_H, d_W)
batch["resp_r"]         # (B,S)
# "Inert for model/loss (read-only)"
```

**Verified:** `grep -rn "resp_disp_mm" --include=*.py .` returns **only `tools/`** — 18 hits
across `exp_resp_oracle.py`, `measure_dvf_z_correction.py`, `dump_predicted_dvf.py`,
`exp_4wok_analysis.py`, `miitt_viz/*`, etc. Zero hits in `training/loss.py`, `training/trainer.py`,
or any model code.

So every training step the project **already knows the exact GT displacement of every input slice
and discards it**, supervising instead through a photometric L1 whose through-plane gradient
docs/19 §2 measured at **0.0067/mm vs 0.0143/mm in-plane** — roughly 2× weaker in exactly the axis
that matters most.

In synthesis-engine terms, the free-supervision channels are:

| Channel | What it gives | Status here |
|---|---|---|
| (a) the label map itself | GT segmentation | available via docs/39 `heart_seg`, unused in loss |
| (b) any functional of it | heart mask, EF, chamber volumes, surfaces | unused |
| (c) inverse of a corruption you applied | denoise / de-alias / de-blur target | not built |
| (d) **the transform you sampled** | **GT DVF** | **sampled and discarded** |
| (e) invariance across appearance draws | contrast invariance | not built |

Channel (d) is not a new capability. It is an **unwired** one.

# 3. What to simulate, and what not to

The governing rule from the synthesis literature is **detect-vs-ignore**: *randomize what you want
the model to ignore; never randomize what you need it to predict.* If the thing you randomize IS
the finding, you have built a detector for its complement.

## 3.1 Respiratory motion — randomize freely, past realism

Pure nuisance. `respiratory.py` applies deform-then-reslice to the **input slices only**;
`gt_target_volume`, `scanner_coords`, `anatomy_bbox`, `content_mask` and `phases` all stay at the
unshifted end-expiration reference (`gpu_aug.py:262-270` docstring). The model's job is to *undo*
it. Wider is strictly better — and docs/08 measures the current sim as **3–50× too large** and
per-slice incoherent versus real OCMR, which has not hurt.

## 3.2 Cardiac motion — randomize too, but keep it cardiac-*shaped*

This was contested during design and the resolution matters.

**Initial objection (wrong, or at least overstated):** under `one_frame_per_slice`, `S == D`, every
plane is observed exactly once at a random phase `t_i`, and the loss asks for the volume at
`t_target`. So nearly every slice must be transported from `t_i` to `t_target` — that mapping *is*
cardiac motion, and it is learnable only because real hearts contract reproducibly. Randomize it
and the mapping becomes unlearnable; the best the model can do is predict the generator's mean,
i.e. zero motion.

**Counter (stronger, and adopted):** real hearts do *not* contract alike. docs/39 records EF
63±10% preserved vs **21±9% DCM**. A population cardiac prior is therefore weak, and a model
leaning on one will systematically under-serve exactly the pathological cases the project cares
about. Randomizing motion forces the model to **read** contraction from slice content rather than
recall a population average — which is the entire point of domain randomization, and is what
SynthMorph does deliberately ("*hyperparameters are not chosen to mimic realistic anatomy… we
select hyperparameters visually to yield shapes and contrasts that far exceed the range of
realistic medical images*").

**The disanalogy with SynthMorph that bounds the payoff.** SynthMorph registers a moving and a
fixed image *of the same anatomy* — the answer is determined by the data. Here each plane `z_i` is
observed once, and the reference anchor is at `z_mid`, a **different** plane. There is no fixed
image for plane `z_i` at the target phase. The correspondence is therefore only **partially
identifiable**:

- **In-plane** contraction is identifiable — cavity area and wall thickness are visible in the
  slice. Randomization should help here, and this is the real win: amplitude tracking across the
  pathological range instead of regression to a normal-EF prior.
- **Through-plane** motion is poorly identifiable. Randomization drives it toward zero.

Under partial identifiability a well-behaved estimator recovers the identifiable component and
shrinks the rest. **That is exactly what is already measured** — docs/07: correlation **+0.87**
(the model reads the motion) but slope **0.42** (it under-scales), plateauing at 7–8 mm against
applied breaths up to 24 mm; docs/33 independently gets slope **0.35**, corr **0.52**. That is not
a bug; it is the correct Bayesian behaviour of an `r`-blind estimator, as docs/04 §5-6 predicted.

**Design consequence:** simulate cardiac motion, push amplitudes well past physiological range
(into and beyond DCM territory), but keep the deformation *cardiac-shaped* — torsion, longitudinal
shortening, radial thickening — so the identifiable in-plane signature stays informative. Widen a
physiologically-structured distribution; do not replace it with an unstructured one.

**Prediction, stated so it can be falsified:** this buys **calibration and OOD robustness**, not
in-distribution PSNR. See §4.

## 3.3 Anatomy — do NOT synthesize from scratch

docs/20 measured a population template at **14.4 dB, below the 16.8 identity floor**. Hearts are
not anatomically aligned in the canonical grid, so there is no population prior to exploit, and a
from-scratch synthetic 4D heart lands in that same unaligned frame.

In the anatomix ablation (external reference, *not* a repo measurement — L2R-Abdomen registration
Dice: **.74** matched real templates / **.68** noise shapes / **.57** mismatched real brain labels),
correspondence tasks are strongly prior-sensitive and a *mismatched* real prior is worse than no
prior. This project already has **1337 pooled subjects** of matched real anatomy. Synthesizing
anatomy trades a matched prior for a worse one to solve a diversity problem docs/58 already solved
by pooling.

**Caveat / open door:** using **real CT-derived cardiac label maps** (TotalSegmentator / MMWHS
style) is a *different* proposal and the docs/20 objection does not apply to it — those are real
anatomy, merely from another modality, i.e. the `.74` regime not the `.68` one. It is worth
considering purely for cross-modality contrast robustness. Its cost: cardiac CT is single-phase or
coarsely gated, so the **beating would be entirely invented** — you inherit the §3.2 identifiability
limit *plus* an anatomy-source domain gap. Not recommended before S0-S3 have run.

## 3.4 Acquisition physics — channel (c), input-only

bSSFP transient, single-shot R=8 undersampling aliasing, intra-frame motion blur. These are
*sampled corruptions whose inverse is the task*, not appearance the target should share, so they go
on the **inputs only**, in the same slot the respiratory path uses.

Anchor number: docs/13 §3 measured single-shot R=8 input at **−3.03 dB, near the identity floor** —
the largest single measured drop in the repo, larger than every model-side lever combined (+0.41
aug, +0.80 composition, +0.03 renderer). It is a *domain gap*, not an appearance wall, so unlike
in-distribution PSNR it is **not** ceiling-bound.

Note `RandGaussianNoised` is already disabled in every aug tier with the correct rationale
(`gpu_aug.py:128-130`: real OOD/real-time degradation is *structured* — aliasing/motion-blur — not
Gaussian). The project identified the right axis and simply has not built it.

## 3.5 Contrast (per-label GMM) — last, and bounded

Do it, but rank it last. Rationale in §6.

# 4. What this will and will not buy

**Will not: in-distribution motion PSNR.** docs/19 §2 — identity **16.8**, model **20.6**,
free-per-pixel direct optimization **20.8/20.9**, G32 **21.2**, oracle **35.0**. The model is
**0.5 dB** from the ceiling of what *any* warp can achieve. Perfect motion estimation is worth
≤0.4 dB. docs/20 closed the renderer escape (+0.03 dB); docs/21 closed the composition escape
(+0.80 realized vs +0.84 ceiling). **The ceiling is architectural.**

**Will not: fix the 0.42 shrinkage.** An L1/L2 regression onto a GT the inputs do not determine
converges to the conditional median of `Δ | inputs`. That *is* the shrinkage. Swapping photometric
L1 for Δ-L2 changes the estimator's variance, not its bias. Anyone claiming GT-DVF lifts the slope
toward 1 without adding an `r` channel (docs/04 §7) is wrong. docs/33's corr 0.52 does prove the
blind posterior is non-degenerate, so headroom exists — bounded at **~1.9 dB** on the breathing
residual.

**Will buy — three separable things:**

1. **A real metric in mm where none exists.** docs/07 §1 states outright: "*There is no motion
   ground truth… this is a plausibility check, not an accuracy metric.*" Sampled motion converts
   every Δ diagnostic in `tools/` from correlation-and-magnitude into **endpoint error in mm**.
   Given how many recent docs are corrections of earlier conclusions, a non-gameable geometric
   readout is the cheapest thing this project can buy.
2. **The OOD relocation bug that photometric L1 structurally cannot see.** docs/46 clean-arm
   predicted Δz: **0.18 mm in-distribution vs MIITT 10.3 mm, ACDC 4.2 mm, OCMR 4.1 mm**. On clean
   OOD stacks the correct displacement is ≈0 and the model relocates anatomy by a centimetre.
   MIITT's cohort floor is 16.0 dB, so a 10 mm spurious shift is buried under the appearance wall.
   A geometric target is the only supervision in the design space that can say *"the answer here
   is zero."*
3. **Gradient path + dynamic-voxel coverage.** `L_dvf` reaches the point head without traversing
   the coverage division `acc/(cov+ε)`, addressing the 2× weak z-gradient without changing the
   renderer. And docs/13 notes the model is barely supervised on the 3-5% of voxels that actually
   move; a DVF loss (or a masked volume loss, §5.2) is uniform over anatomy pixels by construction.

# 5. Implementation

## 5.1 Where synthesis inserts (if/when appearance randomization is added)

**Commit: on `phases`, inside `gpu_aug.gpu_augment_batch`, immediately after
`aug_dict = transforms(aug_dict)` (`gpu_aug.py:317`) and BEFORE the clamp (`:328`) and the
`gt_target_volume` derivation (`:335`).**

The three consumers of appearance all read one tensor:

| Consumer | Site |
|---|---|
| `gt_target_volume = phases_aug[arange(B), t_target]` | `gpu_aug.py:335` |
| input slices `extract_slices_from_phases(batch["phases"], …)` | `gpu_aug.py:392` (resp path `:378`) |
| `batch["phases"] = phases_aug.to(phases.dtype)` | `gpu_aug.py:339` |

Anything upstream of `:328` is automatically coupled for all three. Anything downstream of `:335`
decouples `V_gt` from the inputs and injects the unlearnable residual §1.1 describes.

**So yes — `V_gt` becomes synthetic too. That is not a compromise; it is what keeps the loss
well-posed.**

Signature: `synthesize_appearance(phases_f, label_map, cfg, generator) -> (B,T,D,H,W) float32`,
same shape in/out. Two edits in `gpu_aug.py`: the call site, plus adding `"label_map"` to
`keys`/`mode_dict` in `build_gpu_transforms` (`:92-93`, mode `"nearest"`) so labels are warped by
the same per-subject affine as `phases` (`:117`) and phase-consistency is preserved.

**Randomize per sample; hold constant within a sample.** One draw of `(μ_k, σ_k)` per label,
constant across all `T` phases and all `D` planes of that sample — otherwise cardiac motion becomes
a contrast flicker and the splat's cross-phase agreement is destroyed.

## 5.2 Labels: `heart_seg` alone is nowhere near enough

docs/39 built `heart_seg.nii.gz` (4D, 3-class LV=1 / MYO=2 / RV=3, Task114) + `heart_roi.nii.gz`
for **421 CMRx/MIITT/OCMR/Göttingen + 150 ACDC** units, with `cardiac_phase.csv`. M&Ms ships true
GT masks (validated 320/320, CLAUDE.md). docs/57 has CorSeg running in-env (EF MAE 2.51 pp, r 0.987).

**But coverage is tiny.** From docs/39's own QC statistics (LV cavity median 87 mL, MYO/LV 1.08,
RV/LV 1.23 ⇒ ≈288 mL labeled) against a canonical FOV of 358.4 × 358.4 mm × (D·dz ≈ 144 mm)
≈ 18.5 L, the labeled fraction is **≈1.6%**. *(Arithmetic derived from docs/39 statistics, not
measured on the volumes — recompute before relying on it.)* docs/39 further records that
superior/basal planes are **entirely unlabeled** — atria, valve plane, great vessels have no
Task114 class.

A per-label GMM over `heart_seg` alone therefore repaints ~1.6% of the FOV and leaves lung, chest
wall, fat, liver and the whole basal cap at original CMR contrast. That is cardiac recolouring on a
fixed background — and the frozen DINOv2 stem will key on the background.

**SynthSeg's k-means filler trick is load-bearing, not garnish.** It is what converts 1.6% into
100%: at preprocess time, per subject, k-means the *unlabeled* voxels of phase 00 into K≈16
clusters (intensity + coarse position) and emit `synth_labels_canonical.nii.gz` as `(D,H,W) uint8`
with labels `0..K+2`. The filler labels need not be semantically meaningful — SynthStrip's own
extra-cerebral labels "*do not necessarily represent or differentiate meaningful anatomical
structures – their purpose is to provide intensity and spatial variability*".

**Honest cost accounting:** `heart_seg_canonical.nii.gz` **does not exist today** — only
`heart_roi_canonical` is loaded (`mri_dataset.py:604-620`, consumed at `loss.py:352`). So the
"minimal change" actually costs: one new preprocess transform, one new cached artifact, one new
dataset key, one new aug key. Larger than it first looks.

**Separately and cheaply: the masked volume loss.** `loss.py:194` has the masked variant commented
out. With `heart_seg` you can weight the L1 on anatomy instead of letting static chest wall and
lung dominate the mean — directly addressing docs/13's 3-5%-dynamic-voxel observation. **This needs
no synthesis engine at all** and is the cheapest item in this document.

## 5.3 Sampled-motion module

New file `training/data/synth_motion.py`:

- `sample_smooth_dvf(B,S,D,H,W,cfg) -> (B,S,3,D,H,W)` mm — random ~8³ Gaussian velocity field +
  6 scaling-and-squaring integration steps (diffeomorphic). For the cardiac component, constrain
  the basis to torsion + longitudinal shortening + radial thickening (§3.2) rather than an
  unstructured field.
- `compose(resp_vec, cardiac_field)`.
- `render_inputs(phases[:, t_ref], field, t_seq, z_seq, spacing) -> images (B,S,518,518,3)`,
  reusing `respiratory.extract_slices_with_respiratory_vec`'s grid machinery generalized from
  constant-per-slot to per-pixel grid.

`gpu_aug.gpu_augment_batch`: new branch `if synth_cfg.enable:` → sets `images`,
`gt_target_volume = phases[:, t_ref]`, and `batch["gt_dvf_norm"] (B,S,H,W,3)` in the **same
normalized units as `scanner_coords`**.

`loss.compute_volume_intensity_loss`:

```python
if "gt_dvf_norm" in batch and dvf_weight > 0:
    loss_dvf = ((pos_pred - batch["scanner_coords"] - gt_dvf).abs() * anat_mask).sum() \
               / anat_mask.sum() * dvf_weight
# export metric_dvf_epe_mm ALWAYS (weight 0 ⇒ metric-only mode)
```

**Variant ranking (what is synthetic vs real):**

| Variant | Anatomy | Motion | Appearance | Verdict |
|---|---|---|---|---|
| (i) | real | **sampled** | real | **ADOPT** — exact GT Δ, no anatomy-prior risk |
| (iii) | real | sampled | **synthetic GMM** | adopt as S4 — invariance pressure on top of a correct geometric target |
| (ii) | **synthetic label map** | sampled | synthetic GMM | **REJECT** — docs/20's 14.4 dB template (§3.3) |

## 5.4 Acquisition-physics hook

Same slot as respiratory — after `extract_slices_with_respiratory_vec`, overwriting `images` and
nothing else, so `V_gt` and `Δ_gt` are untouched and it composes with (i) for free.

**Mechanical correction that is easy to get wrong:** these cannot be applied to the
`(B,S,518,518,3)` output. Undersampling aliasing lives in the **256² k-space**; applying it after
the 256→518 bilinear (`gpu_aug.py:239-244`, mirrored in `respiratory.py`) is wrong physics. The
helper must run *inside* both extractors, on `slices_canon` **before** `F.interpolate`. Two call
sites, one shared function.

**Asymmetry worth internalising:** input-only corruption raises the loss *floor* (information is
destroyed) but leaves the optimum at true geometry. Appearance *decoupling* adds an irreducible
*bias* the head cannot express. Corruption is safe; decoupling is not.

## 5.5 Invariance auxiliary loss (channel e) — contested, see §6

```
Δ_A = f(images(x, a_A));  Δ_B = f(images(x, a_B))     # two appearance draws, one geometry
L_inv = λ · mean(‖Δ_A − Δ_B‖₁)
L     = L1(V_canon^A, V_gt^A) + L1(V_canon^B, V_gt^B) + L_inv
```

Hook: `trainer._step`, the single site where `model(...)` and `self.loss(...)` meet. Each branch
carries its own `V_gt` from its own draw, so both L1 terms stay coupled and well-posed; `L_inv`
constrains only Δ, whose true value is appearance-independent by construction. Minimizer sets
intersect at the true geometry — no term fights another.

**Cost:** a genuine second forward through 941M. `B` is pinned to 1 and `S` is the frame-attention
axis, so there is no batch trick — ~2× step time on top of aggft's 2.8× (~27 GB/A40). Mitigation:
`synthesis.inv_every_n: 4`.

## 5.6 Config surface

```yaml
data.augmentation.synthesis:        {enable: false, n_filler_labels: 16, mu_range: [0,255],
                                     sigma_range: [0,35], inv_every_n: 4}
data.augmentation.synth_motion:     {enable: false, prob: 0.5, cardiac_amp_mm: 6.0, ctrl_grid: 8}
data.augmentation.acquisition:      {bssfp: false, aliasing_R: 0, blur_frames: 0}
loss.volume.dvf_weight:             0.0
```

`enable: false` ⇒ the function is never called ⇒ **bit-identical** output. Same discipline
`respiratory` and `diffusion_weight` (`loss.py:210`) already use.

# 6. Staged rollout — each stage independently falsifiable

| Stage | Work | Verify | Kill criterion |
|---|---|---|---|
| **S0** | Wire existing `resp_disp_mm` → `metric_dvf_epe_mm`. ~2 h, zero training risk. | EPE reproduces docs/07 slope 0.42 within 0.03 | If not, the readout is broken — **stop, fix first** |
| **S1** | `dvf_weight > 0` on the respiratory component only, existing data | in-dist PSNR unchanged ±0.15 **and** MIITT clean Δz drops from 10.3 mm | Δz doesn't move ⇒ geometric supervision does nothing here; abandon |
| **S2** | Variant (i): sampled cardiac + resp branch, `prob=0.5`, alongside the real-cine photometric branch | EPE on held-out synthetic < 1.5 mm **and** docs/46 4-cohort PSNR non-regressed | Cross-phase transport degrades toward zero-motion (the §3.2 risk) |
| **S3** | Acquisition physics (bSSFP, R=8 aliasing, blur), input-only | movement against docs/13's −3.03 dB | no recovery of the single-shot gap |
| **S4** | Per-label GMM + filler labels (§5.2), optionally + `L_inv` (§5.5) | pooled OOD PSNR vs the docs/46 C2 baseline | gain ≪ +0.41 dB for 2× step cost |

**S4 is last on purpose.** The entire existing aug stack — ±180° in-plane rotation, translate
16 px, scale ±5%, gamma 0.7-1.5, bias field ±0.5 — measures **+0.41 dB pooled OOD at −0.13 dB
in-dist** (docs/46 C2, survives Bonferroni; MIITT +0.48 p=0.04, ACDC +0.47 p=0.002). A per-label
GMM is a *widening of that same axis*, so the honest prior on its value is a fraction of 0.41 dB.
Against that: MIITT's 5 dB cohort deficit is attributed to **orientation** (~180° off CMRx's mode,
`gpu_aug.py:137-141`) and relocation, not contrast; and docs/08's *OOD-clean paradox* found that the
cohort whose appearance differs most (OCMR real-time bSSFP, real free breathing) is where the model
looks *best* relative to expectation — diagnosed as resolution + splat, not domain shift. A
contrast-brittle model would not behave that way.

**Open disagreement, unresolved:** whether `L_inv` (§5.5) is the highest-value item or the weakest.
*For:* it is the only mechanism that converts randomization into a hard constraint on the trained
output, i.e. SynthMorph-style invariance without decoupling the L1 draws. *Against:* because the
model is a pure transport operator it **cannot** intensity-match anyway, so a coupled GMM draw
already applies genuine invariance pressure implicitly — and 2× step cost on an already
compile-optimized loop (docs/47, 52) is better spent on S2's second branch. Decide empirically at
S4, not now.

# 7. Things to consider / known risks

- **Frozen DINOv2 interaction.** `patch_embed` is a whole ~304M DINOv2 ViT-L, frozen in *both*
  freeze regimes including aggft (CLAUDE.md), fed grayscale replicated to RGB under ImageNet stats
  (`gpu_aug.py:248`, `aggregator.py:239`). SynthSeg-style randomization works partly because the
  encoder trains *from scratch under* the randomization; here it cannot adapt. **Hypothesis
  (untested):** wide draws push inputs off the ImageNet manifold into a module with zero capacity
  to compensate, collapsing tokens. docs/46 C4 measures unfreezing DINO under the *current narrow*
  distribution at +0.21 in-dist / +0.19 OOD, pooled p=0.042 that dies (0.091) without ACDC's 66%
  weight — it says nothing about the interaction with synthesis.
  **Cheap probe, zero training:** push N synthesized draws of one subject through the frozen stem;
  compare patch-token CKA within-subject-across-draws vs across-subjects. If within-draw distance
  ≈ across-subject distance, the stem has erased identity and synthesis must be paired with C4.
- **Learning the simulator.** Train Δ against a sampled DVF and the model learns *the deformation
  prior you sampled from*. docs/20 §TL;DR pt 3 already observed the analogous failure on its
  synthetic known-answer toy: synthesis beat transport only on the population-predictable
  component and **hallucinated the subject-specific component at the population-mean location**.
  Mitigation: keep the sampled-motion branch *alongside* the real-cine photometric branch
  (`prob=0.5`), never as a replacement.
- **A supervised-DVF path existed and was deleted.** `29da7b3 feat(mri)!: remove supervised-DVF
  pipeline from data/loss path` (−563 lines; `MRIDataset` stopped reading
  `dvf_elastix/dvf_frame_*.nii.gz`, `gt_dvfs`/`scale_factors` left the batch), preceded by
  `c714a0e`. **Two mitigations:** (a) that GT was elastix/carmen *registration output* —
  pseudo-labels inheriting a registration algorithm's own errors and smoothness prior, categorically
  weaker than a *sampled* transform; (b) docs/48 records `compute_point_loss` was **never reached**
  (all non-volume weights were 0), so the path was abandoned by architecture pivot, not by
  measurement. **One aggravation:** docs/48 also shows exactly how a `weight: 0.0` loss slot rots
  into 155 dead lines. S0/S1's metric-only mode must be defended by a **test**, not a config default.
- **Sim-to-real is a motion gap, not an appearance gap.** docs/08 measures the respiratory sim as
  3-50× too large *and* per-slice incoherent vs OCMR's small coherent bulk SI slide (n=8 volunteers
  — thin). Fixing respiratory *realism* may matter more than adding appearance variation.
- **Through-plane / obliquity randomization is currently ZERO.** `gpu_aug.py:108-109` hard-zeros
  rotation on slots 1,2 and freezes translate/scale on slot D; no elastic. Measured SAX obliquity
  is real — `|S|` median **0.402**, not 1.0 (CLAUDE.md §Slice order). This is an unmodeled axis of
  real variation and arguably outranks contrast.
- **Slice pitch / count randomization** is currently only whatever the pooled cohort happens to
  contain (D 5-21, dz 5-12 mm).
- **Everything here sits behind two bigger levers.** docs/20 §4 argues the binding constraint is the
  **input contract** (docs/04: `z` known, input `t`/`r` unknown; docs/21's held-out-z collapse
  **18.2 → 13.55**), and docs/10 measures the **splat as 75% of the blur** (0.74× GT sharpness on
  perfectly clean inputs). No synthesis engine touches either.

# 10. Bottom line

The synthesis-engine preconditions hold here — the model is a geometric transport operator and its
photometric loss is geometric in disguise. But the engine's *contrast* axis is the least valuable
part of it for this project: it is bounded by a measured +0.41 dB, and every documented OOD failure
is resolution-, orientation-, or geometry-driven rather than contrast-driven.

The valuable part is **channel (d)**, and it is already half-built: sample the motion, keep the GT,
supervise Δ directly. Start at S0 — two hours, no training, and it either reproduces docs/07's
slope or tells you the readout is broken.

Expect **calibration and OOD robustness, not PSNR**. The 21 dB wall is architectural.
